## Why

Two guarantees are still missing. Accounts can be changed by the table owner, and the application can in principle supply values the server must assign (`id`, `entry_id`, `created_at`, `currency`), so a ledger row could be written with an invented timestamp. And a client cannot ask what a balance was at a past moment: a balance is only ever "now", so it cannot be reproduced, audited or reconciled later. This slice closes both, and the two are linked: an as-of balance is only trustworthy if `created_at` can come from nowhere but the database clock.

## What Changes

- **Infrastructure first, on its own.** Postgres 16 → 17 in `docker-compose.yml`, `AbstractIntegrationTest` and `ContractTestBase` (QA-owned: the image tag only, authorized). Postgres 17 is needed for `transaction_timeout`; on 16 the setting does not exist (`42704`, observed). The volume is recreated (`docker compose down -v`). The whole suite must be green on 17, with no other change, before anything below starts.
- **Accounts are immutable (V5).** `accounts` gets the slice 3 treatment: a `BEFORE UPDATE OR DELETE` row trigger and a `BEFORE TRUNCATE` statement trigger, both running `forbid_ledger_mutation()` (`LDG02`). This stops the owner too; `ledger_app` already lacks `UPDATE`, `DELETE` and `TRUNCATE`.
- **Server-assigned columns cannot be supplied by `ledger_app` (V5).** Table-level `INSERT` is replaced by column-level `INSERT`: `accounts (code, owner_ref, type)`, `journal_entries (idempotency_key, reverses_entry_id)`, `entry_lines (journal_entry_id, line_number, account_id, amount_cents)`. `id`, `entry_id`, `created_at` and `currency` can then only come from their defaults, and `OVERRIDING SYSTEM VALUE` stops working for `ledger_app`. Default privileges flip: a table created later is `SELECT`-able automatically and `INSERT`-able only through its own explicit column-level grant. **BREAKING for the spec** "Tables created by later migrations get the same restricted access", which promised `INSERT` by default.
- **One adapter statement must change first.** The audit the brief asked for found that `JdbcAccountAdapter` inserts `(code, owner_ref, type, currency)`; `currency` is no longer insertable, so the adapter drops it and relies on `DEFAULT 'BRL'` (still read back with `RETURNING`).
- **As-of balance.** `GET /api/v1/accounts/{code}/balance?as_of=<instant>` returns the sum of the account's lines whose entry has `created_at <= as_of` (inclusive, microsecond precision). The response gains `as_of` (the instant echoed in UTC; `null`, key present, when the parameter is absent). An account created after `as_of` answers `200` with `0`, not `404`.
- **The settle window.** `created_at` is the start of the inserting transaction but rows become visible at commit, so an as-of answer could change after the fact. The system answers only for `as_of <= database now() - 60s` (`422 urn:ledger-split-engine:problem:as-of-not-settled` otherwise, future instants included), and every `ledger_app` transaction is bounded at 30s by `ALTER ROLE ledger_app SET transaction_timeout = '30s'` in the init script. The application reads the setting on startup and refuses to start unless `0 < timeout <= 60s / 2` and `max_prepared_transactions` is 0 (the Postgres default): a prepared transaction leaves its session and can become visible long after its `created_at`, which no per-session bound limits.
- **Errors, in this order.** `400` (`as_of` is not an RFC 3339 instant with an explicit offset: uppercase `T`/`Z`, seconds required, 0–6 fractional digits; also empty, repeated, or a malformed percent-encoding, and **any query parameter other than `as_of`**, named in the detail: a silently ignored `asOf` or `AS_OF` would answer a request for the past with the present, the same false-success bug class as slice 1's dropped `owner_ref`) → `404` unknown account (unchanged) → `422` not settled.
- **The same rule on every endpoint (added after the first QA report).** The rule was first built for the balance endpoint only, while `PROJECT-CONVENTIONS.md` already said "every endpoint"; QA's contract tests, written from the conventions, found the gap. A web-layer interceptor now rejects, before any handler runs, a query parameter the endpoint does not declare (`@AcceptedQueryParameters`; no annotation means none) with the same `400`, so `POST /accounts?x=1`, `POST /journal-entries?x=1`, the reversal and `GET /accounts/{code}?as_of=…` are refused too, and a new endpoint cannot forget it. The malformed percent-encoding mapping moves there with it and covers every endpoint.
- **Where the rule lives.** Domain: `SETTLE_WINDOW` and `AsOfNotSettledException`. Port: `databaseNow()` and `balanceOf(code, asOf)`. New use case `ReadAccountBalance` (find account → settle check → sum); the balance controller stops calling ports directly.
- **Scope change: no currency-grouped trigger.** `accounts.currency` is `CHECK (currency IN ('BRL'))`, so a grouped trigger could never see two currencies and could not be tested against real data. The ledger is single-currency by design; the README and `PROJECT-CONVENTIONS.md` record what a second currency would take.
- **Conventions and docs.** `PROJECT-CONVENTIONS.md`: accounts are immutable, server-assigned columns are never insertable, new tables get `INSERT` only through explicit column grants, time ordering is by `created_at` never by `id`, the as-of rules, the use-case-for-rules-in-reads convention, single currency. `README.md`: what the project is and is not, `as_of` with curl examples (`Z`, and `%2B` for positive offsets), why recent instants are refused, the limits.

## Capabilities

### New Capabilities

None. As-of reading extends `account-balances`; the immutability and grant rules extend `ledger-append-only`.

### Modified Capabilities

- `account-balances`: the balance response gains `as_of`; new requirements for reading a balance as of a past instant (inclusive, by `created_at`), the strict `as_of` format and its `400`s, the settle window and its `422`, the rejection of any other query parameter, the fixed order of the balance errors, and the transaction bound (and disabled prepared transactions) with the startup refusal that makes an answer stable.
- `account-registration`, `journal-entries`, `journal-entry-reversal`: one new requirement each, that the endpoint accepts no query parameter (a stray one is a `400` naming it, nothing is written, no key is consumed).
- `ledger-append-only`: the application identity's `INSERT` is limited to the client-supplied columns; server-assigned columns cannot be supplied (including by `OVERRIDING SYSTEM VALUE`); tables created later are read-only for the application until granted (the existing requirement is renamed and reversed); the owner-proof triggers now cover `accounts`.

## Impact

- **Infra:** `docker-compose.yml`, the two Testcontainers images (the contract suite's one is QA-owned: tag only), `docker/initdb/01-create-ledger-app-role.sql`. Every developer recreates their volume once (`docker compose down -v`); the app refuses to start against a database whose `ledger_app` has no bound.
- **Migration:** `V5__immutable_accounts_and_server_assigned_columns.sql` (two triggers, three column-level grants after a table-level revoke, one default-privileges change). Verified end to end on Postgres 16 and on 17.11 in throwaway containers, including the `transaction_timeout` behaviour the as-of guarantee rests on (design.md, Decision 7).
- **Code:** `domain.journalentry` (`SettleWindow`, `AsOfNotSettledException`, `JournalEntryPort`), new `application.journalentry.ReadAccountBalance`, `JdbcAccountAdapter` (no `currency` in the insert), `JdbcJournalEntryAdapter` (`databaseNow`, `balanceOf(code, asOf)`), `AccountBalanceController` and `AccountBalanceResponse`, `ApiExceptionHandler` and `ProblemTypes`, a startup check in `config`, and in `adapter.web` the query-parameter rule shared by every endpoint (`AcceptedQueryParameters`, `QueryParameterInterceptor`, `WebConfiguration`).
- **Tests:** new DB-level, adapter (owner-seeded, backdated `created_at`), use-case (fake port with a controllable clock), controller, end-to-end and real-socket tests; two slice 5 tests and one slice 3 privileges test move or flip (see design.md).
- **QA-owned:** the contract suite's image tag only. No contract test checks the balance body's exact key set (`balanceShape` already fails on its `code` key and uses `containsKeys`), so the baseline should be unchanged: 354 unit tests, 696 contract invocations, 14 skipped, 13 failures. (QA's slice 6 tests, `AsOfBalanceContractTest` and `ImmutableAccountsContractTest`, were added afterwards and are not part of that baseline.)
- **Docs:** `README.md`, `PROJECT-CONVENTIONS.md`.

**Out of scope:** a separate effective (business) date (as-of is by recorded time); account status or closing; `GET /journal-entries/{entry_id}`; account statements and pagination.
